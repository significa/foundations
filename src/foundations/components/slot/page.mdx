## Anatomy

```tsx
<Slot>
  <component />
</Slot>
```

## Features

- **Prop Merging**: Merges the Slot's props onto its child element; the child's own props win, except where they're explicitly `undefined` or `null`
- **Event Handler Composition**: When both pass the same `on*` handler, both run: the Slot's first, then the child's unless the Slot's handler returned `SKIP_CHILD`
- **Style Composition**: Combines styles from both Slot and child element; the child's wins per property
- **ClassName Merging**: Intelligently merges classNames using the `cn` utility
- **Ref Composition**: The Slot's `ref` and the child's own `ref` both receive the element
- **Type Safety**: Full TypeScript support with proper type inference

## Examples

### Basic Usage

Merging props onto a button element.

```tsx
<Slot onClick={() => alert("clicked")} data-foo="bar">
  <button>Click me</button>
</Slot>

/**
 * Renders:
 *  <button data-foo="bar" onClick={() => alert("clicked")}>
 *   Click me
 *  </button>
 */
```

### Using Slottable

Handling multiple children with the Slottable component.

```tsx
<Slottable asChild child={<button>Click me</button>}>
  {(child) => (
    <>
      <span>sufix</span>
      {child}
      <span>prefix</span>
    </>
  )}
</Slottable>

/**
 * Renders:
 *  <button>
 *   <span>sufix</span>
 *   click me
 *   <span>prefix</span>
 *  </button>
 */
```

## Technical Details

The Slot component uses React's `cloneElement` to merge props onto its child element. It handles:

- Prop spreading
- Event handler composition
- Style composition
- ClassName merging
- Ref composition
- Type safety

The child's props take precedence over the Slot's, but event handlers, `className`, `style` and `ref` are combined rather than replaced, so the child keeps its own behaviour and the Slot keeps its own.

On a `className` conflict the Slot's utilities win (`cn(child, slot)`, resolved by tailwind-merge); for `style` and every other prop the child wins. A child prop set to `undefined` or `null` counts as not set.

`Slottable` renders its child through `Slot`, so the same rules apply under `asChild`.

## Blocking the child's handler

If you build an `asChild` component with a disabled state, the child's own `onClick` (a link's, say) still runs while disabled unless your handler returns `SKIP_CHILD`. Calling `event.preventDefault()` stops the navigation but can't be the signal, because it's a shared browser flag that doesn't say who set it: an ancestor's `onClickCapture` may already have set it, and a check on it would either skip the child when nothing asked or miss a real veto. This is how `Button` guards its disabled and loading states:

```tsx
import { SKIP_CHILD } from "#/foundations/components/slot/slot.tsx";

const handleClick = (event: React.MouseEvent<HTMLButtonElement>) => {
  if (isLoading || disabled) {
    event.preventDefault(); // stops the link navigating or the form submitting
    return SKIP_CHILD; // stops the child's own onClick
  }
  return onClick?.(event);
};
```
