Each cell is a real `<input>` element. The root manages all state, keyboard navigation, and focus logic — cells and separators are purely presentational, composed freely as children.

## Anatomy

```tsx
<OTPInput>
  <OTPInput.Hidden name="otp" />
  <OTPInput.Cell />
  <OTPInput.Divider />
  <OTPInput.Cell />
</OTPInput>
```

### OTPInput.Hidden

Extends the `input` element, omitting `type` and `value` which are managed internally. Only needed when the OTP field is inside a `<form>`.

### OTPInput.Cell

Extends the `input` element. Each cell is labelled `Digit 1`, `Digit 2`, … by default; pass `aria-label` to override it (see [Localising the cell labels](#localising-the-cell-labels)).

Cells are square and shrink to fit a narrow container. The root is as wide as its cells; give it `w-full` to spread them across the container.

### OTPInput.Divider

Extends the `div` element. Renders an em dash by default, overridable via `children`.

### Masked

Hides the entered characters behind discs with `-webkit-text-security`, on a `type="text"` input. A `type="password"` field would make password managers offer to save the PIN as a password. Pair it with `autoComplete="off"` for a PIN, so the browser doesn't offer one-time codes either.

Set `inputMode="text"` for codes that include letters. This switches the mobile keyboard to the full keyboard and lifts the digit-only restriction.

### Localising the cell labels

The default `Digit n` labels are English. Pass your own `aria-label` to each cell, with the cell's position:

```tsx
<OTPInput>
  {Array.from({ length: 6 }, (_, i) => (
    <OTPInput.Cell key={i} aria-label={t("otp.digit", { position: i + 1 })} />
  ))}
</OTPInput>
```
