## Features

- **Animated Indicator**: Slides between tabs with CSS anchor positioning (no animation in Firefox yet)
- **Keyboard Navigation**: Full keyboard support for tab navigation
- **Orientation Support**: Both horizontal and vertical layouts
- **Controlled & Uncontrolled**: Flexible state management options
- **ARIA Support**: Full accessibility implementation
- **Custom Styling**: Extensible styling through className props

## Anatomy

```tsx
<Tabs>
  <Tabs.Items>
    <Tabs.Item value="..." />
  </Tabs.Items>
  <Tabs.Panels>
    <Tabs.Panel value="..." />
  </Tabs.Panels>
</Tabs>
```

Each `Tabs.Item` pairs with the `Tabs.Panel` of the same `value`, so tabs can be rendered
conditionally (`{canBill && <Tabs.Item value="billing">}`) without shifting the others.

## API Reference

### Tabs

The root container component that manages the state and behavior of the tabs.

If the selected tab is no longer rendered, no tab is selected (in both modes) until one is
picked, and the first tab stays reachable by keyboard.

### Tabs.Items

The container for tab buttons. Provides proper ARIA attributes and keyboard navigation. Render
each `Tabs.Item` as a direct child (conditionals and `.map()` are fine). `Tabs.Items` reads their
values to keep a tab reachable when the selected one isn't rendered, and it doesn't look inside
fragments.

### Tabs.Item

The individual tab button component. With `asChild`, render a `button` or a link: they activate
on Enter (and a button on Space) natively. Don't give the child its own `id`; the tab's generated

## Accessibility

The Tabs component follows the [WAI-ARIA Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/). It implements all the required ARIA attributes and keyboard interactions.

## Best Practices

1. **Content Organization**:
   - Use meaningful tab labels that describe their content
   - Keep tab labels concise
   - Order tabs in a logical sequence

2. **Performance**:
   - Lazy load tab content when possible
   - Consider using dynamic imports for heavy content

3. **Accessibility**:
   - Ensure tab labels are descriptive
   - Maintain a logical tab order
   - Consider users who navigate with keyboard only

4. **Mobile Considerations**:
   - Ensure touch targets are large enough
   - Consider scrollable tabs for many items
   - Test with different screen sizes
